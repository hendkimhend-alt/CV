## 1. 문제 제기

PBL 13장의 노면 마스크(`*_2_road_mask.jpg`)를 확인한 결과, ROI가 도로를 제대로 잡지 못하는 사진이 여러 장 있었다.

| 문제 유형 | 해당 사진 | 증상 |
|---|---|---|
| **그림자** | United_States_005996, United_States_004830 | 나무 그림자가 진 노면이 마스크에서 빠짐. 005996은 앞쪽 도로 대부분이 빠져 마스크 7%로 검증 FAIL |
| 젖은 노면 반사 | Norway_009625, Japan_010993 | 하늘이 비친 밝은 노면이 빠짐 |
| 수평선 위 누수 | Japan_000156, Japan_000107, United_States_004952 | 안개 낀 나무 · 건물 · 언덕까지 마스크가 올라감 |
| 색이 다른 노면 | India_002374 | 먼지 낀 밝은 중앙 도로가 빠짐 |
| 근접 촬영 | Japan_001959 | 화면 전체가 노면인데 자동 마스크 실패 → 검출을 건너뜀 (`skipped_manual_required`) |
| 대체로 잘 됨 | China_MotorBike_002159, Norway_008315, Japan_013055, China_MotorBike_002209 | 013055는 차량 옆 그늘 일부, 002209는 옆 차로가 빠지지만 큰 문제는 아님 |

**영향**: 노면 마스크는 검출 결과를 거르는 데만 쓰이지 않는다. 검출기 입력 범위와 배율도 정한다 (자세한 내용은 2-8).
- 후보 박스 면적의 50% 이상이 마스크 위여야 인정된다 (`min_road_overlap: 0.5`). 노면이 마스크에서 빠지면 그 안의 균열 · 포트홀은 검출돼도 버려진다.
- 마스크가 바뀌면 검출기 입력(마스크 외접 사각형 + 16px를 잘라 긴 변 1024로 맞춘 영상)도 바뀐다. 그래서 마스크가 바뀌지 않은 곳의 검출 결과도 달라질 수 있다.

**검증의 한계**: 마스크 검증은 면적 · 최대 연결 요소 · 구멍 · 시드 일치만 본다 (2-7). 도로 절반이 잘려도 면적 10%만 넘으면 PASS가 된다. 또 FAIL이어도 마스크가 비어 있지 않으면 그대로 검출에 쓴다.

이번 작업은 이 중 **그림자** 문제만 다룬다.

## 2. 기존 ROI 알고리즘 (수정 전)

ROI는 **"확실히 도로인 칸(시드)을 몇 개 고른 뒤, 그 색과 비슷한 화소로 퍼져 나가는"** 방식이다. 이 장은 수정 전 코드(`final0 - 복사본/`)의 동작이다. 바뀐 점은 4장에 따로 적는다.

### 2-1. 전체 흐름

```
원본 → 긴 변 1024로 축소, 1024 이하면 그대로 (작업 영상)      road_mask.py
     → 화소 특징 지도(Lab 색 · 기울기 · 질감) · 32px 칸 격자 특징   grid_features.py
     → (1) 칸마다 도로다움 점수 → 시드 최대 5개 선택              seeds.py
     → (2) 시드마다 비슷한 화소로 퍼짐 → 시드별 영역 합치기         region_growing.py
     → (3) 정리 (closing · opening · 구멍 채우기 · 작은 조각 제거)  mask_refine.py
     → 원본 크기로 복원                                         road_mask.py
     → (4) 검증 PASS / FAIL                                     mask_validation.py
```

설정은 모두 `configs/preprocessing.json`의 `roi` · `validation`에 있다.

### 2-2. 특징 지도와 격자

| 특징 | 계산 | 쓰는 곳 |
|---|---|---|
| Lab 색 | 작업 영상을 σ2 가우시안으로 흐린 뒤 Lab 변환 (L 0~100) | 시드 점수 · 영역 확장 색 비교 |
| 기울기 (경계 강도) | 흐리지 않은 L을 σ1로 흐리고 소벨 크기 ÷ 8 = **화소당 L 변화량** | 영역 확장의 벽 (≤ 5) · 칸의 경계 밀도 (> 6인 화소 비율) |
| 질감 | L의 \|라플라시안\|을 σ2로 평균 | 시드 질감 점수 · 영역 확장 질감 비 |

격자는 **한 칸이 32×32px**이다. 예를 들어 1024×576 작업 영상은 32열 × 18행, 600×600 원본(rdd_dev에 많음)은 19열 × 19행이다. 칸마다 평균 L · a · b, 채도 √(a² + b²), 질감 평균, 경계 밀도, 칸 중심 위치, 채움 비율(가장자리 칸이 영상 안에 든 비율)을 계산한다.

### 2-3. 시드 점수: 칸마다 도로다움

칸마다 6가지 요소를 매기고 **가중 기하평균**으로 합친다.

| 점수 요소 | 계산 (설정값) | 높게 나오는 칸 |
|---|---|---|
| 위치 | cy^0.5 × (1 − 0.3·\|2cx − 1\|) (cx, cy = 칸 중심, 0~1) | 화면 **아래쪽 · 가운데** |
| 무채색 | exp(−(채도/18)²) | **회색** (채도 0 → 1, 18 → 0.37, 28 → 0.09) |
| 균일함 | exp(−경계 밀도/0.2) | 강한 경계(차량 · 건물 윤곽)가 적은 칸 |
| 질감 | 2~45면 1, 더 매끈하면 (t/2)², 더 거칠면 45/t | 하늘처럼 매끈하지도, 나무처럼 거칠지도 않은 칸 |
| 밝기 | L 10~80이면 1, 바깥은 15 폭에 걸쳐 직선으로 감소 (L 0 → 0.33, L 95 → 0) | 너무 밝지 않은 칸 |
| 이웃 유사도 | 이웃 8칸마다 exp(−색 거리/6) × 그 이웃의 예비 점수(앞 5요소)를 평균 | 주변 칸과 색이 비슷하고 주변도 점수가 높은 칸 |

- 가중치는 이웃 유사도 1.5, 나머지 1.0이다 (합 6.5).
- **한 요소만 낮을 때의 영향은 생각보다 작다.** 나머지가 모두 1이면, 가중치 1인 요소 하나가 0.1이어도 전체 점수는 0.1^(1/6.5) ≈ 0.70이다. 0.6 아래로 떨어지려면 그 요소가 0.036 미만이어야 한다. (가중치 1.5인 이웃 유사도는 0.1이면 ≈ 0.59, 경계는 ≈ 0.11)
- 밝기 점수는 사실상 아주 밝은 칸(하늘)만 크게 깎는다. 아주 어두운 칸(L 0)도 0.33이라 전체 점수는 0.84배로만 줄어든다.

### 2-4. 시드 선택

| 규칙 | 내용 |
|---|---|
| 후보 | 점수 ≥ 0.6, 칸의 절반 이상이 영상 안 |
| 순서 | 점수 높은 칸부터 |
| 간격 | 이미 고른 시드와 가로 또는 세로 중 한쪽으로 3칸 이상 떨어짐 (max(\|Δ행\|, \|Δ열\|) ≥ 3) |
| 개수 | 최대 5개. 3개 미만이면 경고만 남기고 그대로 진행, 0개면 마스크 없음 (FAIL) |
| 1번 시드(최고 점수)와의 일관성 | 색 거리 √(Δa² + Δb²) ≤ 5 · 밝기 차 \|ΔL\| ≤ 25 · 질감 비 ≤ 2배 |

- 일관성 검사의 "색 거리"는 설정 키 이름(`max_chroma_distance_to_best`)과 달리 **채도 크기의 차가 아니라 a·b 평면의 거리**다. 채도가 같아도 색상이 다르면 탈락한다.
- 결과적으로 시드는 **화면 아래 · 가운데의 회색 노면 칸**에 잡히고, 2번 이후 시드는 1번과 색 · 밝기가 비슷한 칸만 뽑힌다.

### 2-5. 영역 확장: 시드에서 퍼지기

시드마다 다음을 반복하고, 결과를 모두 합친다.

| 순서 | 동작 |
|---|---|
| ① | 시드 칸의 평균 색(L, a, b), a·b 표준편차 σ_ab, 질감 중앙값을 **기준**으로 삼음 |
| ② | 작업 영상 전체에서 아래 조건을 **모두** 만족하는 화소에 표시 |
| ③ | 표시된 화소의 8-연결 덩어리 중 **시드 칸에 가장 많이 걸친 하나**만 채택 (시드에서 출발해 이웃으로 번지는 것과 같음) |
| ④ | 그 덩어리가 시드 칸의 30% 이상을 덮어야 인정 |

②의 조건 (ΔL, Δa, Δb = 화소 − 기준색):

| 조건 | 식 | 막는 것 |
|---|---|---|
| 색 | √((0.35·ΔL)² + Δa² + Δb²) ≤ min(6 + σ_ab, 9) | 색이 다른 재질 |
| 밝기 차 | \|ΔL\| ≤ 30 | 흰 차선 · 하늘 |
| 경계 강도 | 기울기 ≤ 5 | 연석 · 차선 · 차량 윤곽 (퍼짐이 여기서 멈춤 = **벽**) |
| 질감 | 기준 질감의 0.35배 ~ 2.5배 | 매끈한 하늘 · 거친 나무 |

색 거리에서 L은 0.35배만 보므로, 색이 같다면 밝기 차 약 17~26(= 6~9 ÷ 0.35)까지 받아들인다. **그보다 진한 그림자, 또는 색까지 바뀐 그림자는 빠진다.**

### 2-6. 정리와 복원

| 순서 | 동작 (설정값) |
|---|---|
| ① | closing (타원 7px): 좁은 틈 메우기 |
| ② | opening (타원 5px): 가는 돌기 · 점 제거 |
| ③ | 테두리에 닿지 않는 구멍 중 영상 면적 2% 이하인 것만 채움 |
| ④ | 영상 면적 1% 미만인 조각 제거 (가장 큰 덩어리만 남기지는 않음 → 중앙분리대로 나뉜 도로 유지) |
| ⑤ | 작업 영상을 줄였을 때만: 원본 크기로 선형 보간 후 0.5 이상 = 노면. 원본을 그대로 썼으면 그대로 사용 |

### 2-7. 검증 (PASS / FAIL)

| 지표 | 조건 |
|---|---|
| 면적 | 마스크 ÷ 영상 ≥ 0.10 |
| 최대 연결 요소 | 가장 큰 덩어리 ÷ 마스크 ≥ 0.80 |
| 구멍 | 구멍 ÷ (마스크 + 구멍) ≤ 0.15 |
| 시드 일치 | 최종 마스크 안에 든 시드 비율 ≥ 0.60 |

시드가 없거나 마스크가 비어도 FAIL이다. 하나라도 못 넘으면 FAIL이다. 형태(아래쪽 도로가 잘렸는지, 화면 위까지 퍼졌는지)는 보지 않는다.

### 2-8. 노면 마스크가 검출에 쓰이는 방식

`run_final.py` · `configs/detection_final.json`의 `integration` 기준:

| 순서 | 동작 | 마스크의 영향 |
|---|---|---|
| ① | 검증 FAIL이어도 마스크가 비어 있지 않으면 **검증 안 된 마스크**로 그대로 사용 (`on_fail: use_candidate`). 비어 있으면 건너뜀 (`skipped_manual_required`) | PASS / FAIL 자체는 검출 결과를 바꾸지 않음 |
| ② | 마스크 외접 사각형 + 16px만 잘라 긴 변 1024로 맞춤 (`crop_to_road`) | 마스크가 바뀌면 **검출기 입력 범위 · 배율이 바뀜** |
| ③ | 검출기 입력 보정 (가우시안 · 막대 닫힘 · 언샤프 · CLAHE) | 마스크 안에만 적용 |
| ④ | 포트홀 후보의 "주변 고리 대비 거칠기"를 마스크 안 화소로만 계산 | 마스크 밖은 포트홀 후보가 될 수 없음 |
| ⑤ | 후보 박스 면적의 50% 이상이 마스크 위여야 인정 (`min_road_overlap: 0.5`) | 마스크 밖 후보 버림 |

## 3. 문제 원인

### 3-1. 처음 가정과 실제 측정

처음에는 "그림자는 어두워질 뿐"이라고 보고, 시드 일관성 검사의 어두운 쪽 밝기 제한만 풀었다 (1단계, 4-2). 그러나 PBL 13장 결과가 **전혀 바뀌지 않았다**. United_States_005996의 격자 값을 직접 확인한 결과:

| 영역 | L (밝기) | a (초록−빨강) | b (파랑−노랑) | 채도 | 무채색 점수 |
|---|---|---|---|---|---|
| 해가 드는 노면 | 75~86 | ≈ 0 | **+6 ~ +8** | 4~8 | 0.8 이상 |
| 그림자 진 노면 | 23~33 | 0~4 | **−18 ~ −28** | 18~28 | 0.1~0.4 |
| (참고) 잔디 · 004830 | - | **−15 ~ −19** | +10 ~ +17 | - | - |

그림자 노면은 **밝기만이 아니라 색도 크게 바뀌어** 두 단계에서 모두 걸러지고 있었다.

| 단계 | 그림자 노면을 막은 조건 | 1단계로 풀렸나 |
|---|---|---|
| 시드 선택 | 무채색 점수가 낮아 도로다움 점수는 떨어지지만, 기하평균이라 0.6은 넘을 수 있다 (005996 앞쪽 그림자 칸도 후보였음, 4-4 그림). **실제로 막은 것은 1번 시드(햇빛 노면)와의 색 거리 ≈ 30 > 5**이고, 밝기 차 ≈ 50 > 25도 함께 걸렸다 | ✘ 밝기 제한만 풀었고, 같은 검사의 색 거리 제한(5)에 먼저 걸림 |
| 영역 확장 | 햇빛 쪽 시드와의 색 거리 ≈ 35 > 9, **그리고** 밝기 차 ≈ 50 > 30 (4-5 예시) | ✘ 영역 확장 조건은 그대로 |

그래서 그림자 노면을 받으려면 영역 확장에서 **색과 밝기를 함께** 허용하는 조건이 필요했다 (2단계).

### 3-2. 왜 파래지는가

| 빛 | 색 | 해가 드는 곳 | 그림자 속 |
|---|---|---|---|
| 직사광선 | 노랑~흰색 | 받음 | **차단** |
| 하늘빛 (산란광) | **파랑** | 받음 | 받음 (이것만 남음) |

그림자 속 노면은 파란 하늘빛만 받으므로 어두워지면서 b가 음수(파랑) 쪽으로 이동한다. 조명 변화는 대략 **어두워지는 방향 + 파랑−노랑 축(b축)** 을 따라 일어난다. 그래서 "어두워지고 b가 파란 쪽으로 간 변화"를 덜 엄격하게 보면, 다른 재질(초록 잔디, 노란 흙)은 여전히 걸러낼 수 있다는 것이 수정의 생각이다. 실제 조건이 어떤 화소까지 통과시키는지는 4-3에 정리했다.

> 젖은 노면은 반대로 하늘을 비춰 **밝아지고** 파래진다 (Norway_009625: 시드 L 9~22 → 반사 L 40~80). 이번 수정은 어두워지는 쪽만 허용하므로 반사는 해결되지 않는다.

## 4. 코드 변경사항

### 4-1. 바꾼 파일

| 파일 | 변경 내용 | 단계 |
|---|---|---|
| `src/preprocessing/seeds.py` | `consistent_with_best`: 1번 시드와의 밝기 제한을 밝은 쪽(25 유지)과 어두운 쪽(새 키)으로 분리 | 1단계 |
| `src/preprocessing/region_growing.py` | `acceptance_mask`: 그림자 조건(OR) 추가 · 질감 하한 완화 · 그림자 조건의 높이 제한 / `grow_regions`: 시드 y좌표 전달 | 2단계 |
| `configs/preprocessing.json` | 아래 설정 키 추가 (4-6) | 1 · 2단계 |

나머지 파일은 수정 전과 같다. `README.md`와 `src/preprocessing/README.md`는 아직 수정 전 동작으로 적혀 있어 갱신이 필요하다 (예: preprocessing "바꾼 것: 없음", 시드 밝기 제한 \|ΔL\| ≤ 25).

### 4-2. 1단계: 시드 선택 밝기 제한 분리

| 1번 시드와의 일관성 | 이전 | 이후 |
|---|---|---|
| 색 거리 √(Δa² + Δb²) | ≤ 5 | 같음 |
| 밝기 차 | \|ΔL\| ≤ 25 | 밝은 쪽 ≤ +25 · **어두운 쪽 ≤ −50** |
| 질감 비 | ≤ 2배 | 같음 |

색 거리 제한이 그대로라서, 1번 시드가 햇빛 노면에 잡히면 파랗게 바뀐 그림자 칸은 여전히 시드가 되지 못한다. 그래서 아래 4-4 그림의 두 사진은 시드 위치가 이전과 이후에 **같다**. 그림자 영역은 자기 시드를 갖는 대신 **햇빛 쪽 시드에서 퍼져 들어간다**. 1단계는 색은 비슷하고 더 어두운 칸이 있는 사진(dev 13장)에서만 시드를 바꿨다 (5-10).

### 4-3. 2단계: 영역 확장 조건 변경

2단계는 성격이 다른 두 변경을 함께 켠다 (`shadow.enabled` 하나로).

**(A) 그림자 조건 (OR로 추가).** 아래를 모두 만족하는 화소는 기존 색 조건 · 밝기 차 조건(\|ΔL\| ≤ 30)을 못 넘어도 표시한다.

| 조건 | 식 | 설정 키 · 값 |
|---|---|---|
| 어두워짐 | 0 < −ΔL ≤ 60 (시드보다 어둡고, 어두워진 정도가 60 이하) | `max_darkening` 60 |
| 색 | √(Δa² + Δb'²) ≤ 7. Δb' = Δb가 음수(파랑)면 Δb × 0.2, 양수면 그대로 | `blue_shift_weight` 0.2 · `color_threshold` 7 |
| 높이 | 시드 칸 중심보다 **작업 영상 높이의 10% 넘게 위인 행**에서는 끔. **아래쪽은 제한 없음**. 시드마다 따로 적용 | `max_rise_ratio` 0.1 |

이 조건이 실제로 통과시키는 색 범위는 다음과 같다 (Δa = 0일 때 Δb는 −35 ~ +7, Δb = 0일 때 \|Δa\| ≤ 7).

| 화소 | Lab 변화 | 그림자 조건 |
|---|---|---|
| 그림자 진 노면 | 어두워지고 b가 파란 쪽 | **통과** (의도) |
| 색은 그대로, 어둡기만 한 영역 (촬영 차량 보닛 · 검은 차체 · 트럭 아래 그늘) | 어두워짐, Δa ≈ 0 · Δb ≈ 0 | **통과** (의도 밖. 파란 쪽 이동을 요구하지 않으므로) |
| 조금 노란 쪽 | Δb +7 이내 | 통과 |
| 잔디 · 나무 | a가 음수 (초록) | \|Δa\| > 7이면 차단 |
| 흙 · 먼지 | b가 양수 (노랑) | Δb > +7이면 차단 |
| 먼 경치 (나무 · 건물) | 공기 때문에 어둡고 파랗게 보임 | 색으로는 통과 → **높이 제한**으로만 막음 |

**(B) 질감 하한 완화 (모든 화소).** 질감 하한(기준 질감 × 0.35)에 clip(화소 L ÷ 시드 L, 0.3, 1)을 곱한다. 빛이 줄면 \|라플라시안\|도 줄기 때문이다. 이 완화는 그림자 조건과 상관없이 **시드보다 어두운 모든 화소**(기존 색 조건으로 받던 화소 포함)에 적용되고, 높이 제한도 받지 않는다. (A)와 (B)의 효과를 나눠 본 실험은 없다.

**최종 조건:**

```
표시 = [ (색 거리 ≤ min(6+σ_ab, 9)  AND  |ΔL| ≤ 30)  OR  그림자 조건 ]
       AND  기울기 ≤ 5
       AND  기준 질감 × 0.35 × clip(L/L시드, 0.3, 1) ≤ 질감 ≤ 기준 질감 × 2.5
```

이전 / 이후 비교:

| 조건 | 이전 | 이후 |
|---|---|---|
| 색 · 밝기 | 색 거리 ≤ 6 + σ_ab (최대 9) **그리고** \|ΔL\| ≤ 30 | (왼쪽 조건) **또는** 그림자 조건 (A) |
| 경계 강도 | 기울기 ≤ 5 | 같음 (그림자 화소에도 적용) |
| 질감 | 기준 질감의 0.35배 ~ 2.5배 | 하한 × clip(L/L시드, 0.3, 1) (B) |
| 연결 · 채택 | 시드 칸과 이어진 덩어리, 시드 칸 30% 이상 | 같음 |

이전에는 그림자 노면이 색 · 밝기 조건에서 막혀 **표시 자체가 안 됐다**. 이후에는 그림자 조건으로 표시되고, 시드 영역과 **이어지면** 함께 채택된다. 반대로, 그림자 조건을 통과한 띠가 원래 끊겨 있던 비노면 영역과 시드 영역을 **이어 주는** 일도 생긴다 (5-8 Norway_008137).

### 4-4. 그림으로 보기: 시드와 퍼짐

- **(a)** 도로다움 점수 지도 (밝을수록 높음) · 흰 칸 = 점수 0.6 이상 (시드 후보) · 번호 칸 = 선택된 시드 (1번 = 최고 점수)
- **(b) 이전 / (c) 이후** 퍼진 영역 · 색 = 그 영역을 키운 시드 (겹치면 나중 시드 색) · **하늘색 = 이후에 그림자 조건으로 새로 추가된 부분**

### 4-5. 예시: 그림자 화소 하나의 판정

United_States_005996의 실측 범위 안에서 고른 **예시 값**:

| | L | a | b |
|---|---|---|---|
| 기준 (햇빛 노면 시드) | 80 | 0 | +7 |
| 화소 (그림자 노면) | 30 | 1 | −23 |
| 차이 | ΔL = −50 | Δa = +1 | Δb = −30 |

| 판정 | 이전 | 이후 |
|---|---|---|
| 기존 색 · 밝기 조건 | 색 거리 = √(17.5² + 1² + 30²) ≈ 34.7 > 9 → **탈락**<br>\|ΔL\| = 50 > 30 → **탈락** | 같음 (탈락) |
| 그림자 조건 | 없음 | 어두워짐 50 ≤ 60 ✔<br>Δb' = −30 × 0.2 = −6 → √(1² + 6²) ≈ 6.1 ≤ 7 ✔<br>시드보다 아래 (또는 위 10% 이내) ✔ → **통과** |
| 최종 | 노면 아님 | 경계 강도 · 질감 조건도 통과하고 시드 영역과 이어지면 **노면** |

- 같은 화소라도 b가 +7 넘게 노란 쪽(흙)이거나 \|Δa\| > 7(초록 · 잔디)이면 그림자 조건에서도 탈락한다.
- 반대로 **색은 그대로이고 어두워지기만 한 화소**(Δa = Δb = 0, ΔL = −50)는 √(0² + 0²) = 0 ≤ 7로 통과한다. 촬영 차량 보닛이나 트럭 아래 그늘이 노면으로 들어오는 이유다 (5-9).

### 4-6. 설정과 되돌리기

설정 위치: `configs/preprocessing.json`

```json
"roi": {
  "seeds": {
    "max_lightness_distance_to_best": 25.0,
    "max_shadow_darkening_to_best": 50.0
  },
  "region_growing": {
    "shadow": {
      "enabled": true,
      "max_darkening": 60.0,
      "color_threshold": 7.0,
      "blue_shift_weight": 0.2,
      "max_rise_ratio": 0.1,
      "min_texture_scale": 0.3
    }
  }
}
```

| 키 | 단계 | 뜻 |
|---|---|---|
| `seeds.max_shadow_darkening_to_best` | 1 | 1번 시드보다 어두운 칸의 밝기 차 상한 (없으면 25와 같음) |
| `shadow.enabled` | 2 | (A) 그림자 조건과 (B) 질감 하한 완화를 함께 켬 |
| `shadow.max_darkening` | 2 (A) | 시드보다 어두워진 정도의 상한 |
| `shadow.color_threshold` | 2 (A) | √(Δa² + Δb'²) 상한 |
| `shadow.blue_shift_weight` | 2 (A) | 파란 쪽(Δb < 0) 차이에 곱하는 배율 |
| `shadow.max_rise_ratio` | 2 (A) | 시드 위로 작업 영상 높이의 이 비율까지만 그림자 조건 적용 (`null` = 제한 없음) |
| `shadow.min_texture_scale` | 2 (B) | 질감 하한에 곱하는 밝기 비율의 최솟값 |

**되돌리기**: `shadow.enabled: false`, `max_shadow_darkening_to_best: 25.0`이면 수정 전 코드와 같은 결과가 나온다. 코드상 질감 배율이 1.0이 되고, 밝기 제한이 \|ΔL\| ≤ 25와 같아진다. rdd_dev 563장의 정확도 · 마스크 수치가 수정 전 코드 결과와 전체 · 그룹별 모두 일치함을 확인했다.

| 효과 | 국가 | 근거 |
|---|---|---|
| 좋음 | United_States | 미검증 마스크 9 → 5 · 균열 맞춤 +2 · 균열 오검출 −19 |

정리:

- **ROI 면적은 좋아졌지만 rdd_dev 정확도로는 이어지지 않았다.** 그림자 속 균열을 새로 맞힌 사진도 있지만, 검출 영역(잘라내기 · 배율)이 바뀌며 기존 맞춤을 잃은 사진이 더 많다(−10장).
- **검증 FAIL → PASS는 그 자체로 검출을 바꾸지 않는다.** FAIL 마스크도 그대로 검출에 쓰기 때문이다 (2-8 ①). 검출에 영향을 주는 것은 마스크 모양의 변화다.
- **포트홀 오검출 증가는 그림자 영역에서 나왔다.** 오검출이 많이 늘어난 사진 4장을 확인한 결과, 새 포트홀 박스는 나무 그림자 · 앞유리 프레임 그림자 · 보닛 쪽 어두운 띠 위에 있었다 (5-9). 포트홀 검출이 "주변보다 거칠고 안쪽이 어두운 곳"을 찾는데, 그림자 경계가 이 조건에 맞는 것으로 보인다.
- **그림자 조건은 생각보다 넓다.** 파란 쪽 이동을 요구하지 않아, 색 변화 없이 어둡기만 한 영역(보닛 · 트럭 아래 그늘)도 받는다 (4-3).
- **그림자 조건은 "다리" 역할도 한다.** 원래는 끊겨 있던 비노면 영역(숲)이 그림자 조건을 통과한 어두운 띠를 통해 시드 영역과 이어지면, 높이 제한과 관계없이 퍼진다.
- 현재 설정을 그대로 확정하기보다, 아래 개선점을 반영한 뒤 다시 비교하는 것이 좋다.

## 7. 개선점

| 우선순위 | 개선점 | 내용 | 근거 | 난이도 · 위험 |
|---|---|---|---|---|
| 1 | 그림자 조건을 조명 변화 방향으로 좁히기 | 어두워질수록 일정량 이상 파란 쪽 이동을 요구 (예: Δb ≤ −k·\|ΔL\|). 색 변화 없이 어둡기만 한 보닛 · 차체 · 트럭 아래 그늘을 막음 | 4-3, 4-5, 5-9 (Japan_000121, Czech_003360, Japan_002128) | 쉬움 · 중간 (색 변화가 작은 그림자 노면도 일부 빠질 수 있음 → PBL 005996으로 확인) |
| 2 | 그림자 영역 포트홀 기준 강화 | 그림자 조건으로만 들어온 화소를 따로 기록해 검출기까지 전달하고, 그 위 포트홀 후보는 고리 비 기준을 높이거나 조명에 덜 흔들리는 거칠기(예: log 밝기 기울기)로 계산. 고칠 곳: `acceptance_mask` → `grow_regions` → `road_mask` → `preprocessing/pipeline` → `run_final.prepare` → `to_detector_input` → `texture_potholes` | 포트홀 오검출 +54 (5-9) | 중간~어려움 · 중간 (후보를 버리면 그림자 속 진짜 포트홀도 잃음) |
| 3 | 화면 아래 촬영 차량 영역 제외 | 지금 높이 제한은 시드 위쪽만 막는다. 1로 막히지 않으면 화면 맨 아래 가로로 긴 어두운 띠를 그림자 조건 대상에서 제외 | Japan_000121, Czech_003360 (5-9) | 중간 · 낮음 |
| 4 | 다리 누수 막기 | 2단 연결: 기존 조건 덩어리(core)를 먼저 구하고, 그림자 화소는 core에 붙은 것만 채택. 그림자 화소를 거쳐 새로 이어진 영역에는 높이 제한이나 면적 상한을 적용. 그대로 막으면 그림자 띠 너머의 햇빛 노면도 잘리므로 함께 확인. 풀밭 위 시드(Norway_008137 5번)를 거르는 것도 검토 | Norway_008137 (5-8) | 중간 · 중간 |

| 7 | 균열 맞춤 손실 원인 확인 | 맞춤을 잃은 10장을 잘라내기 · 배율 변화 / 마스크 경계 / 보정 영역 변화로 나눠 확인. 잘라내기 없이 전체 영상 + 마스크 필터로 검출 입력 배율을 고정하는 실험. Czech 균열 오검출 +38 원인 확인 | 5-6, 5-8, 6장 | 중간 · 낮음 |

- 1 · 5 · 6은 쉽고 부작용의 원인을 직접 고치므로 먼저 한다.
- 그다음 2 · 3 · 4 · 7을 하고, rdd_dev 563장으로 다시 비교하는 것을 권한다.

### 재현 방법

```bash
# 수정 후 (현재 설정)
conda activate cv2026
python run_final.py                    # rdd_dev 563장 → final-result/run_<시각>/
python run_final.py --no-images        # 그림 없이 CSV만
python run_final_PBL.py                # PBL 13장 → final-result-PBL/run_<시각>/
```

`configs/preprocessing.json`에서 바꿔 비교하는 설정:

| 설정 | `roi.region_growing.shadow.enabled` | `roi.seeds.max_shadow_darkening_to_best` |
|---|---|---|
| 수정 전과 같음 | `false` | `25.0` |
| 1단계만 | `false` | `50.0` |
| 2단계만 | `true` | `25.0` |
| 수정 후 (현재) | `true` | `50.0` |

- `run_final.py`와 `run_final_PBL.py` 모두 `opencv-contrib-python`(cv2.ximgproc)이 필요하다. 시스템 기본 python(OpenCV 4.10, contrib 없음)으로는 실행되지 않는다.
- 출력을 파이프나 파일로 넘길 때는 UTF-8 출력을 켠다 (cp949 출력 오류 방지). bash: `PYTHONIOENCODING=utf-8 python run_final.py`, PowerShell: `$env:PYTHONIOENCODING='utf-8'; python run_final.py`.
