## 1. 문제 제기

PBL 13장의 노면 마스크(`*_2_road_mask.jpg`)를 확인한 결과, ROI가 도로를 제대로 잡지 못하는 사진이 여러 장 있었다.

| 문제 유형 | 해당 사진 | 증상 |
|---|---|---|
| **그림자** | United_States_005996, United_States_004830 | 나무 그림자가 진 노면이 마스크에서 빠짐. 005996은 앞쪽 도로 대부분이 빠져 마스크 7%로 검증 FAIL |
| 젖은 노면 반사 | Norway_009625, Japan_010993 | 하늘이 비친 밝은 노면이 빠짐 |
| 수평선 위 누수 | Japan_000156, Japan_000107, United_States_004952 | 안개 낀 나무 · 건물 · 언덕까지 마스크가 올라감 |
| 색이 다른 노면 | India_002374 | 먼지 낀 밝은 중앙 도로가 빠짐 |
| 근접 촬영 | Japan_001959 | 화면 전체가 노면인데 마스크 실패 (`aligned_manual_required`) |
| 잘 된 사진 | China_MotorBike_002159, Norway_008315 | - |

**영향**: 검출 결과는 노면 마스크와 50% 이상 겹쳐야 인정된다 (`min_road_overlap: 0.5`). 노면이 마스크에서 빠지면 그 안의 균열 · 포트홀은 검출돼도 버려진다.

**검증의 한계**: 마스크 검증은 면적 · 최대 연결 요소 · 구멍 · 시드 일치만 본다. 도로 절반이 잘려도 면적 10%만 넘으면 PASS가 된다.

이번 작업은 이 중 **그림자** 문제만 다룬다.

## 2. 문제 원인

### 2-1. ROI 동작 방식

```
격자(32×32) 특징 → 시드 선택 → 영역 확장 → 정리 → 검증(PASS/FAIL)   (단계별 자세한 내용은 3-1)
```

| 단계 | 파일 | 그림자를 막는 조건 |
|---|---|---|
| 시드 선택 | `src/preprocessing/seeds.py` | 무채색 점수 (채도가 높으면 시드 후보에서 탈락) · 첫 시드와 채도 차 5, 밝기 차 25 이내 |
| 영역 확장 | `src/preprocessing/region_growing.py` | 색 거리 최대 9 · 밝기 차 30 이내 · 경계 강도(밝기 기울기) 5 이하 · 질감 비율 0.35~2.5배 |

### 2-2. 처음 가정과 실제 측정

처음에는 "그림자는 어두워질 뿐"이라고 보고 밝기 조건을 풀었으나 (3장의 1단계) PBL 13장 결과가 **전혀 바뀌지 않았다**. United_States_005996의 격자 값을 직접 확인한 결과:

| 영역 | L (밝기) | a (초록−빨강) | b (파랑−노랑) | 채도 | 무채색 점수 |
|---|---|---|---|---|---|
| 해가 드는 노면 | 75~86 | ≈ 0 | **+6 ~ +8** | 4~8 | 0.85 이상 |
| 그림자 진 노면 | 23~33 | 0~4 | **−18 ~ −28** | 18~28 | ≈ 0.1 |
| (참고) 잔디 · 004830 | - | **−15 ~ −19** | +10 ~ +17 | - | - |

그림자 노면은 밝기 조건까지 가기 전에 **색(채도) 조건**에서 이미 걸러지고 있었다.

- 무채색 점수 ≈ 0.1 → 시드 후보(점수 0.6 이상)에 들지 못함
- 해가 드는 쪽 시드와의 색 거리 ≈ 30 → 영역 확장 상한 9를 크게 넘음

### 2-3. 왜 파래지는가

| 빛 | 색 | 해가 드는 곳 | 그림자 속 |
|---|---|---|---|
| 직사광선 | 노랑~흰색 | 받음 | **차단** |
| 하늘빛 (산란광) | **파랑** | 받음 | 받음 (이것만 남음) |

그림자 속 노면은 파란 하늘빛만 받으므로 어두워지면서 b가 음수(파랑) 쪽으로 이동한다. 조명 변화는 대략 **파랑−노랑 축(b축)** 을 따라 일어나므로 이 방향만 허용하면 다른 재질은 계속 걸러진다.

| 재질 | Lab에서 다른 점 | 파란 쪽만 허용 시 |
|---|---|---|
| 그림자 노면 | b가 음수로 이동 | 허용 |
| 잔디 · 나무 | a가 음수 (초록) | 계속 차단 |
| 흙 · 먼지 | b가 양수 (노랑) | 계속 차단 |

> 젖은 노면은 반대로 하늘을 비춰 **밝아지고** 파래진다 (Norway_009625: 시드 L 9~22 → 반사 L 40~80). 이번 수정은 어두워지는 쪽만 허용하므로 반사는 해결되지 않는다.

## 3. 코드 변경사항

### 3-1. ROI 작동 방식: 시드를 어디에 잡고 어떻게 퍼지나

ROI는 **"확실히 도로인 칸(시드)을 몇 개 고른 뒤, 그 색과 비슷한 화소로 퍼져 나가는"** 방식이다.

```
원본 → 긴 변 1024로 축소 → 32×32 칸으로 나눔
     → (1) 칸마다 도로다움 점수 → 시드 3~5개 선택          ◀ 이후: 어두운 쪽 밝기 제한만 완화
     → (2) 시드마다 비슷한 화소로 퍼짐 → 시드별 영역 합치기   ◀ 이후: 그림자 조건 추가
     → 정리(구멍 채우기 · 작은 조각 제거) → 원본 크기 → 검증 PASS/FAIL
```

#### (1) 시드를 어디에 잡나

영상을 32×32 칸으로 나누고, 칸마다 6가지 점수를 곱해(기하평균) **도로다움 점수**를 매긴다. 한 요소라도 0에 가까우면 전체 점수가 낮아진다.

| 점수 요소 | 높게 나오는 칸 | 이유 |
|---|---|---|
| 위치 | 화면 **아래쪽 · 가운데** | 차량 카메라에서 도로는 보통 아래 가운데에 있음 |
| 무채색 | **회색** (채도 낮음) | 아스팔트는 무채색 |
| 균일함 | 강한 경계(차량 · 건물 윤곽)가 적음 | 노면은 넓고 고름 |
| 질감 | 너무 매끈하지도(하늘) 거칠지도(나무) 않음 | 아스팔트 특유의 잔질감 |
| 밝기 | 너무 어둡지도 밝지도 않음 (L 10~80) | 하늘 · 깊은 그늘 제외 |
| 이웃 유사도 | 주변 칸과 색이 비슷하고 주변도 점수가 높음 | 도로는 넓게 이어짐 |

점수를 매긴 뒤 다음 규칙으로 시드를 고른다.

| 규칙 | 이전 | 이후 |
|---|---|---|
| 후보 | 점수 0.6 이상인 칸 | 같음 |
| 순서 | 점수 높은 칸부터, 서로 3칸 이상 떨어지게, 최대 5개 | 같음 |
| 1번 시드(최고 점수)와의 일관성 | 채도 차 ≤ 5 · **밝기 차 ±25** · 질감 2배 이내 | 채도 · 질감 같음 · 밝기는 **밝은 쪽 +25 / 어두운 쪽 −50** |

- 결과적으로 시드는 **화면 아래 · 가운데의 회색 노면 칸**에 잡힌다.
- 1번 시드가 햇빛 드는 노면에 잡히면, 그림자 칸은 점수가 0.6을 넘어도 **채도 차(5 초과)** 때문에 시드가 되지 못한다. 이후 버전에서도 채도 제한은 그대로라, 아래 두 사진의 시드 위치는 이전과 이후가 **같다**. 그림자 영역은 자기 시드를 갖는 대신 **햇빛 쪽 시드에서 퍼져 들어간다**.

#### (2) 어떻게 퍼지나

시드마다 다음을 반복하고, 결과를 모두 합친다.

| 순서 | 동작 |
|---|---|
| ① | 시드 칸의 평균 색(L, a, b)과 질감을 **기준**으로 삼음 |
| ② | 영상 전체에서 기준과 비슷한 화소에 표시 (아래 조건) |
| ③ | 표시된 화소 중 **시드 칸과 이어진 덩어리만** 채택 (시드에서 출발해 이웃으로 번지는 것과 같음) |
| ④ | 그 덩어리가 시드 칸의 30% 이상을 덮어야 인정 |

강한 경계(밝기 기울기 > 5)는 표시되지 않으므로 **벽** 역할을 한다. 연석 · 차선 · 차량 윤곽에서 퍼짐이 멈추는 이유다.

②의 "비슷한 화소" 조건 (ΔL, Δa, Δb = 화소 − 기준색):

| 조건 | 이전 | 이후 |
|---|---|---|
| 색 | 색 거리 √((0.35·ΔL)² + Δa² + Δb²) ≤ 6 + 시드 색 표준편차 (최대 9)<br>**그리고** \|ΔL\| ≤ 30 | (왼쪽 조건)<br>**또는 그림자 조건**: 기준보다 어둡고(최대 60) · √(Δa² + Δb'²) ≤ 7 · 시드 높이 근처<br>(Δb' = Δb가 음수(파랑)면 0.2배, 양수면 그대로) |
| 경계 강도 | 밝기 기울기 ≤ 5 | 같음 |
| 질감 | 기준 질감의 0.35배 ~ 2.5배 | 하한을 밝기 비율만큼 낮춤 (최소 0.3배) |

이전에는 그림자 노면이 색 조건에서 막혀 **표시 자체가 안 됐고**, 이후에는 그림자 조건으로 표시되어 시드 영역과 **이어지면** 함께 채택된다.

#### (3) 그림으로 보기

- **(a)** 도로다움 점수 지도 (밝을수록 높음) · 흰 칸 = 점수 0.6 이상 (시드 후보) · 번호 칸 = 선택된 시드 (1번 = 최고 점수)
- **(b) 이전 / (c) 이후** 퍼진 영역 · 색 = 그 영역을 키운 시드 (겹치면 나중 시드 색) · **하늘색 = 이후에 그림자 조건으로 새로 추가된 부분**
- 그림의 % = 정리 전 퍼진 면적 (정리 후 최종 마스크 면적과 조금 다름)

United_States_005996 — 시드 3개는 모두 먼 쪽 햇빛 노면에 잡힘. 앞쪽 그림자 칸도 흰 칸(후보)이지만 1번 시드와 채도 차가 커서 탈락. 이전에는 햇빛 노면만 퍼져 7%, 이후에는 그림자 노면까지 퍼져 37%.

![시드와 퍼짐 United_States_005996](docs/report_img/seed_United_States_005996.jpg)

United_States_004830 — 시드 5개는 왼쪽 햇빛 차로에 잡힘. 이후에는 오른쪽 그림자 차로로 퍼졌지만, **시드 위 10% 높이 제한**에서 가로로 끊김 (6장 개선점 2 · 3).

![시드와 퍼짐 United_States_004830](docs/report_img/seed_United_States_004830.jpg)

#### (4) 예시: 그림자 화소 하나의 판정

United_States_005996의 실측 범위 안에서 고른 **예시 값**:

| | L | a | b |
|---|---|---|---|
| 기준 (햇빛 노면 시드) | 80 | 0 | +7 |
| 화소 (그림자 노면) | 30 | 1 | −23 |
| 차이 | ΔL = −50 | Δa = +1 | Δb = −30 |

| 판정 | 이전 | 이후 |
|---|---|---|
| 기존 색 조건 | 색 거리 = √(17.5² + 1² + 30²) ≈ 34.7 > 9 → **탈락**<br>\|ΔL\| = 50 > 30 → **탈락** | 같음 (탈락) |
| 그림자 조건 | 없음 | 어두워짐 50 ≤ 60 ✔<br>Δb' = −30 × 0.2 = −6 → √(1² + 6²) ≈ 6.1 ≤ 7 ✔<br>시드 근처 높이 ✔ → **통과** |
| 최종 | 노면 아님 | 경계 · 질감 조건도 통과하고 시드 영역과 이어지면 **노면** |

같은 화소라도 b가 양수(노랑 · 흙)나 a가 크게 음수(초록 · 잔디) 쪽으로 달랐다면 그림자 조건에서도 탈락한다.

### 3-3. 그림자 허용 조건

기존 조건을 그대로 두고, 아래를 모두 만족하는 화소를 **추가로** 노면으로 받는다 (OR).

| 조건 | 내용 | 설정 키 | 값 |
|---|---|---|---|
| 어두워짐 | 시드보다 어둡고, 어두워진 정도가 상한 이내 | `max_darkening` | 60 |
| 색 | a 차이는 그대로, b의 **파란 쪽(−) 차이만 축소**해 색 거리 계산 | `blue_shift_weight` | 0.2 |
| 색 거리 상한 | 위 색 거리가 이 값 이하 | `color_threshold` | 7 |
| 높이 제한 | 시드 위로 영상 높이의 이 비율까지만 그림자 조건 적용 | `max_rise_ratio` | 0.1 |
| 질감 하한 | 하한 × (화소 밝기 / 시드 밝기), 최소 이 배율 | `min_texture_scale` | 0.3 |

설정 위치: `configs/preprocessing.json`

```json
"roi": {
  "seeds": {
    "max_lightness_distance_to_best": 25.0,
    "max_shadow_darkening_to_best": 50.0
  },
  "region_growing": {
    "shadow": {
      "enabled": true,
      "max_darkening": 60.0,
      "color_threshold": 7.0,
      "blue_shift_weight": 0.2,
      "max_rise_ratio": 0.1,
      "min_texture_scale": 0.3
    }
  }
}
```

**되돌리기**: `shadow.enabled: false`, `max_shadow_darkening_to_best: 25.0`이면 수정 전 코드와 같은 결과가 나온다 (rdd_dev 563장의 정확도 · 마스크 수치가 수정 전 코드 결과와 전체 · 그룹별 모두 일치함을 확인).

정리:

- **ROI 자체는 좋아졌지만 rdd_dev 정확도로는 이어지지 않았다.** 그림자 속 균열을 새로 맞힌 사진도 있지만(+6장), 검출 영역이 바뀌며 기존 맞춤을 잃은 사진이 더 많다(−10장).
- **포트홀 오검출 증가의 원인은 그림자다.** 오검출이 많이 늘어난 사진 4장을 확인한 결과 새 포트홀 박스는 나무 그림자 · 앞유리 프레임 그림자 · 보닛 쪽 어두운 띠 위에 있었다 (4-9). 포트홀 검출이 어두운 덩어리를 찾기 때문이다.
- **그림자 조건은 "다리" 역할도 한다.** 원래는 끊겨 있던 비노면 영역(숲)이 그림자 조건을 통과한 어두운 띠를 통해 시드 영역과 이어지면, 높이 제한과 관계없이 퍼진다.
- 현재 설정을 그대로 확정하기보다, 아래 개선점을 반영한 뒤 다시 비교하는 것이 좋다.

### 재현 방법

```bash
# 수정 후 (현재 설정)
conda activate cv2026
python run_final.py                    # rdd_dev 563장 → final-result/run_<시각>/
python run_final_PBL.py                # PBL 13장 → final-result-PBL/run_<시각>/

# 수정 전과 같은 결과: configs/preprocessing.json에서
#   roi.region_growing.shadow.enabled = false
#   roi.seeds.max_shadow_darkening_to_best = 25.0
```

- `run_final.py`는 `opencv-contrib-python`(cv2.ximgproc)이 필요하다. 시스템 기본 python(OpenCV 4.10, contrib 없음)으로는 실행되지 않는다.
- 출력을 파이프나 파일로 넘길 때는 `PYTHONIOENCODING=utf-8`을 붙인다 (cp949 출력 오류 방지).
