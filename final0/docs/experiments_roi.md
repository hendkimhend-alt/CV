# ROI 실험 기록 (브랜치 sj/roi-closeup · 출발점 = 그림자-개선버전_1.0.1)

결정 규칙은 **실험 전에** 적는다. 지표는 균열 · 포트홀 각각 R · P · 가짜/장 (in50, `run_final.py`와 같음).

## R1 사진별 정규화 (10/14)

**문제 (제공 사진 진단에서 일반화)**: ROI의 절대 기준(경계 판정 6 · 경계 벽 5 · 시드 질감 2~45)은 보통 사진에 맞춘 값이다.
촬영 조건이 바뀌면 사진 전체의 기울기 · 질감 값이 통째로 이동해 양쪽으로 틀린다.
- 너무 가까움 (제공 Japan_001959): 자갈 알갱이로 질감 104 · 기울기 5.6 → 시드 0개 → ROI 0% (검출 건너뜀)
- 너무 흐림 (제공 Japan_000156): 기울기 0.28 → 경계 벽 사라짐 → 나무 · 집으로 샘
- 개발 563장에서 시드 0개 사진은 0장 (근접 road_full 81장도 최고 칸 점수 ≥ 0.78)

**바꾼 것**: `roi.features.normalize` — 사진 아래 가운데(행 0.6~1 · 열 0.25~0.75)의 기울기 · 질감 중앙값을
기준값(개발 튜닝 394장 중앙값의 중앙: 기울기 0.7743 · 질감 16.0391)에 맞추는 배율을 지도 전체에 곱함. 배율은 0.25~4로 자름.
그 뒤 고정 기준은 그대로. 기준값 · 영역 · 배율 범위는 튜닝 세트에서만 정했고 결과를 보고 바꾸지 않는다.

**비교할 것 (4개 + 기준)**

| 이름 | 설정 |
|---|---|
| R1-0 기준 | 정규화 끔 (= 그림자 브랜치 그대로) |
| R1-G | 기울기만 |
| R1-T | 질감만 |
| R1-GT | 둘 다 |
| R1-GT↓ | 둘 다 · 배율 0.25~1 (줄이기만 = 가깝거나 거친 사진에만 작동) |

**결정 규칙 (미리)**
1. 튜닝 394장에서 기준 대비 조건을 모두 만족하는 안만 후보:
   균열 R 하락 ≤ 0.01 · 균열 가짜/장 증가 ≤ 0.2 · 포트홀 가짜/장 증가 ≤ 0.1
2. 후보 중 균열 R이 가장 높은 안 (같으면 균열 가짜/장이 적은 안). 후보가 없으면 R1은 **안 넣음**.
3. 고른 안을 검증 169장에서 같은 조건으로 확인. 만족하면 **넣음**, 아니면 **안 넣음**.
   검증 차이는 짝지은 부트스트랩 95% 범위(2000번 · seed 20261013)를 같이 적는다 (판정에는 쓰지 않음 · 참고).
4. 같이 적을 것: 검증 FAIL(검증 안 된 마스크) 수 · 마스크가 바뀐 사진 수 · 노면 비율 평균.
5. 제공 사진은 판정에 쓰지 않는다. 결정 뒤 ROI만 1회 그림으로 확인 (Japan_001959 · 000156 · 000107).

**이후 처리 (10/14 사용자 결정 · 실행 중 · 결과 보기 전)**: ROI 작업은 R1로 마무리한다.
- R1 넣음 → 고른 안을 최종 ROI로 사용
- R1 안 넣음 → 정규화는 끄고, **시드가 0개라 마스크가 비면 화면 전체를 ROI로** 쓰는 예외 처리만 넣음 (개발 563장에는 해당 사진 0장 → 개발 결과 그대로)

**최종 결정 (10/14 · 사용자 확인)**: R1 **안 넣음** — 규칙상으로는 R1-T가 통과했지만, 결과를 확인하다 규칙이 못 잡은 구조적 실패를 찾음.
- 마스크가 가장 크게 줄어든 인도 3장(India_003741 · 002320 · 000618)은 기준 영역(아래 가운데)에 **촬영 차량 보닛**이 들어 있음 →
  매끈한 보닛 때문에 질감을 ×3.0~3.6 키움 → 진짜 도로가 너무 거칠어 보여 시드에서 빠지고 **시드가 보닛에 박혀 ROI = 보닛만** (41% → 6% 등).
